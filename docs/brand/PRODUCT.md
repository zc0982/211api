# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

- **主要用户：开发者（优先）。** 国内开发者，日常用 Claude Code、Codex、Cursor 等 AI 编码工具，或在自己的代码里直接调用大模型。他们要的是：一个 Key、一个地址调通全部主流模型，接入不折腾，调用稳定，按量付费。
- **次要用户：团队与企业。** 把大模型接进自家产品的团队。除了开发者的需求，还关心对账、预算控制、开发票和对公付款。
- 两类用户都要服务好，但取舍冲突时以开发者体验为先。

## Product Purpose

211API 是统一的大模型 API 网关（中转站）：用一个兼容 OpenAI / Anthropic 协议的接口，接入全球主流大模型。

成功的标准：
- 用户迁移时只需把 `base_url` 换成 211API 的地址、替换 `api_key`，原有代码、SDK 和工具都不用重写。
- 每一次调用都能查清楚去向和花费。

## Positioning

核心差异是**透明、可追溯**：每一次调用的路由节点、首字延迟、输入/输出 tokens 和费用都逐笔记录，账单能对到每一次请求。这是第一卖点。

稳定与速度（多节点智能路由、上游异常时自动切换）和价格也要讲，但排在透明之后。具体定价策略以运营确认为准。

## Operating Context

- **协议**：兼容 OpenAI 与 Anthropic 协议，模型名称与官方一致。
- **模型供应商**：OpenAI、Claude（Anthropic）、Gemini（Google）、Grok（xAI）四家。
- **生态工具**（首页「生态兼容」区展示）：Claude Code、Codex、Cursor、DeepSeek Harness、Pi、Hermes、OpenCode、OpenClaw。工具通过环境变量切换到 211API。
- **站点一级入口**：首页、注册、模型价格、密钥、控制台、关于。
- **控制台**：调用明细（按时间、模型、状态筛选，搜索请求 ID，导出 CSV，展开查看单次调用链路：鉴权 → 路由 → 上游 → 计费）。
- **计费货币**：控制台和账单用人民币；模型价格表按美元 / 每 1M tokens 展示（当前为示例）。

## Capabilities and Constraints

已出现在设计稿中的能力（文案来自 Figma 首页 v2，上线前需与实际功能逐项核对）：
- 统一接口：一个 Key、一个地址调用全部模型。
- 智能路由：多节点实时测速，上游异常时毫秒级切换。
- 全链路追踪：鉴权、路由、上游、计费逐跳记录。
- 按量计费：用多少付多少，没有月费。
- 用量与预算控制：每个密钥可设额度、速率与告警，超出预算自动暂停。
- 安全合规：密钥加密存储，传输全程 TLS，请求内容不落盘、不留存。
- 调用日志保留 30 天，可导出对账。

尚未确定：
- 正式域名：稿子里一律用 `https://YOUR_DOMAIN/v1` 占位。
- 生产技术栈：目前只有 Figma 设计稿。
- FAQ 答案：6 个问题里只有「如何从官方 API 迁移到 211API？」有真实答案，其余 5 个的答案还是复制的占位文本。
- 定价：模型价格表里的数字是示例。

## Brand Commitments

- 产品名：**211API**。
- Logo：二次元「星狐」（2026-11 起取代学士帽）。一只狐狸代表一个入口；全身版身后 4 条尾巴代表通往各家模型的多条路由，金色尾尖和头像两耳之间的金星代表「每一次调用的清晰去向」。学士帽定稿保留作历史参考，线上代码替换前仍是学士帽。

## Product Principles

1. **透明优先**：每一次调用可查、可对账，是产品的第一承诺；其他卖点不能挤掉它。
2. **迁移只改一行**：兼容官方协议和模型名，不要求用户重写代码或学习新概念。
3. **数字有来源**：展示的指标、价格和规模要么来自真实接口，要么明确标为示例。
4. **开发者优先，兼顾团队**：默认按开发者的使用场景设计，同时给团队留出对账、预算和发票的路径。
