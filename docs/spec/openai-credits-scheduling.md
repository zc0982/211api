# OpenAI 积分与重置卡调度

## 可用性与阈值

- 可消费积分与额度重置卡是两种资源。自动重置卡阈值用于触发用卡流程，不能在积分可用时单独阻断请求，包括用量尚未达到 100% 的窗口。
- 积分快照须在 8 小时有效期内，且 `has_credits=true` 或 `unlimited=true`；已耗尽、缺失、过期或格式无效的快照不提供调度豁免。
- 自动重置卡状态为无卡、查询中、失败或重置中，都不应抹掉有效积分；后台用卡通知和已有重置流程继续执行。
- 独立的管理员停调阈值继续逐窗口生效。积分仅豁免已耗尽窗口的额度停调，不绕过另一个未耗尽窗口的提前停调阈值。
- 最新上游 429 的明确积分耗尽状态优先于旧缓存；保留有界重试与运行时冷却，不能用积分无限重试。

## 共享入口与回归

- 高级调度、legacy 调度、批量负载选择、数据库复核及 WebSocket 续接复用 `shouldAutoPauseOpenAIAccountByQuota`。
- `openai_credits_regression_test.go` 覆盖 5h/7d 用量 99%、自动重置阈值 99%、有积分但无重置卡；修复前返回 `quota_auto_reset_pending_*`，修复后可被实际账号选择器选中。
- 回归同时覆盖重置卡各运行态、独立停调阈值、缺失/耗尽/过期积分、逐窗口豁免和最新 429 优先级。
