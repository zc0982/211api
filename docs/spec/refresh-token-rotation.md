# Refresh Token 轮转与超时恢复

## 不变量

- 轮转先完成用户状态、密码版本和会话指纹校验，再准备 access token 与唯一后继 refresh token。
- 后继由 JWT 密钥和旧令牌做带固定用途前缀的 HMAC-SHA256 派生；不同实例使用同一配置时可恢复同一后继，无需在 Redis 存储 bearer token 明文。登录初始令牌继续使用随机数。
- Redis 原子写入后继、登记用户/家族撤销索引，并把旧键改为短时轮转回执。不得采用“先删除旧令牌，再单独签发新令牌”。
- 回执最多保留 30 秒，且不超过旧令牌原有剩余时间。相同旧令牌的并发/重试可以成功返回同一个后继，不能创建多个后继；重复调用不延长回执或后继的 TTL。
- 仅直接后继仍有效时允许恢复；后继已轮转、过期或撤销后，旧回执不得恢复或创建任何令牌。超过回执窗口仍按无效令牌处理。
- 恢复时读取后继的实际元数据，重新校验用户状态、密码版本和已绑定的会话指纹，避免从旧的未绑定元数据绕过新绑定。
- 单令牌撤销须处理其回执指向的直接后继；用户/家族撤销与轮转原子互斥，清理其索引包含的全部令牌与回执，避免扫描和删除之间漏掉新后继。
- 回执只含后继哈希，旧版本读取时有效期为零并拒绝刷新；身份/版本元数据保留在 Go 编码的后继数据中，不经过 cjson 重编码，以免丢失 int64 精度；脚本在写入前检查索引类型，避免类型错误造成部分写入。

## 失败语义

提交前失败保留旧令牌；提交后丢失响应返回服务暂不可用，客户端可在回执窗口内重试恢复同一后继。不能把 Redis 超时当成“确定未执行”并盲目重新签发不同令牌，也不能恢复被撤销的会话。

前端现有刷新逻辑在网络错误、429 和 5xx 时保留本地会话，因此本次不修改前端。恢复不保证 Redis 长期不可用或超过 30 秒后的会话继续有效。

## 验证

- 注入 Redis 脚本已提交但返回网络超时的故障，覆盖原请求 503、跨实例重试成功、重试得到同一后继及后继轮转后的旧令牌失效。
- 覆盖提交前失败、不同后继竞争、同一后继并发、窗口/原 TTL 边界、用户/家族/单令牌撤销、用户禁用与密码变更、损坏索引不得消费旧令牌。
- 使用真实 Redis 运行 Lua，验证大 int64 身份与密码版本、后继会话绑定、索引登记和撤销；运行完整 unit 与 service/repository race 检查。

## 发布兼容性

已有随机 refresh token 可直接进入新轮转流程，无数据库迁移。旧二进制会把轮转回执视为已过期，不会重复兑换，但可能中断这次短时恢复；更新时应整体切换认证实例，避免新旧版本混跑。JWT 密钥仍需在实例之间保持一致。
