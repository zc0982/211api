# 使用记录的缓存命中率

用户端和管理端展示上游实际命中的输入 Token 占全部输入 Token 的比例。分子取计费转换前的上游缓存读取量。粘性会话切换时，按缓存价格计费的未命中输入仍计入分母，只有上游实际读取的部分计入分子。

- 每条记录的分母由未缓存输入、缓存读取和缓存写入组成。写入总数为正时直接使用；否则取该记录 5m、1h、30m、12h 写入明细之和。输出 Token 不参与计算。
- 每条调用在「延迟」的「输出 TPS」下方显示「缓存率」。顶部「总 Token」卡片及趋势图先按记录确定分子和分母，再分别求和，覆盖当前筛选范围内的所有分页。
- 升级前的记录若有未缓存输入，或缓存读取为零，可以还原上游读取量。若未缓存输入为零且缓存读取为正，旧数据无法区分真实命中和故障切换优惠。此类记录及包含它的汇总显示未知。旧的小时、日预聚合在重新计算前缺少原始统计，也显示未知。
- 有输入且确认零命中时显示 `0.0%`。分母为零或命中率未知时，汇总和明细显示 `—`，趋势图留空。
- 用户 CSV 使用一位小数的百分比文本，管理员 Excel 使用可计算的百分比数值。两种导出的缓存命中率均位于原有列之后，未知或无输入时单元格留空。
